## 0. 먼저 정리해야 할 것 — 층위 문제

지금 네비게이션은 8개인데 **성격이 이미 두 종류로 섞여 있다.**

| 종류 | 항목 |
|---|---|
| 주제 분류 | Travel / Food & Shopping / Beauty & Lifestyle / Culture |
| 형식·면 | Latest / Business Desk / Issues / Card News |

이번 세 코너는 **셋 다 주제도 형식도 아닌 "도구·레퍼런스"**다. 같은 줄에 넣으면 11개가 되고,
모바일에서는 이미 가로 스크롤 상태라 실질적으로 안 보이는 항목이 생긴다.

**판단의 근거**: 우리 트래픽은 사실상 전부 구글에서 개별 글로 직접 들어온다.
**네비게이션은 발견 장치가 아니라 신뢰 장치이자 내부링크 장치다.** 그러므로 모든 코너가
네비에 올라갈 필요가 없고, 올라가면 오히려 손해다.

### 배치 결론

| 코너 | 네비 | 홈 | 진짜 유입 경로 |
|---|---|---|---|
| **Prices** | **추가한다** (1칸) | 타일 + 전용 블록 | 본문 → 가격표 역링크 (글 34편) |
| **Seoul** | 추가하지 않음 | 타일 1칸 | Travel 랜딩 + 동네 글 7편 상호링크 |
| **This Month** | 추가하지 않음 | Latest 상단 배지 | 인스타/릴스 + Food & Shopping 랜딩 |

Prices만 네비에 올리는 이유: **셋 중 유일하게 "다시 오는" 페이지**다. 나머지 둘은 검색 유입 후
읽고 끝나는 성격이라 네비 칸을 쓸 값어치가 낮다.

홈 섹션 타일은 현재 `lg:grid-cols-5` 한 줄이다. **6개로 늘려 3×2 두 줄로 바꾼다**
(Travel / Food & Shopping / Beauty / Culture / Business / **Seoul**). Prices는 타일이 아니라
Business Desk 블록처럼 **전용 블록**을 하나 더 둔다 — 표가 들어가야 값어치가 보이기 때문이다.

## 1. 순서 — 왜 Seoul → Prices → This Month 인가

| | 착수 비용 | 기존 자산 | 유지 비용 | 수익 연결 |
|---|---|---|---|---|
| **Seoul** | 낮음 (허브만) | **글 7편 완성** | 낮음 | 아고다 (직접) |
| **Prices** | 높음 (데이터 모델) | 가격 250개, 글 34편 | **높음 (월 1회)** | 아마존 (직접) |
| **This Month** | 중간 | 없음 | **매우 높음 (월 고정)** | 아마존 + 릴스 |

**Seoul을 먼저 하는 이유는 콘텐츠를 하나도 새로 안 써도 되기 때문이다.** 이미 있는 7편을
묶는 것만으로 코너가 선다. 그래서 **"코너를 만드는 패턴" 자체를 가장 싸게 검증할 수 있고**,
그 과정에서 나온 허브 컴포넌트를 Prices가 그대로 재사용한다.

**Prices를 두 번째로 두는 이유는 유지 리듬을 먼저 몸에 익혀야 하기 때문이다.**
가격표는 낡으면 없느니만 못하다. Seoul 허브를 한 달 굴려보고 "월간 점검"이 실제로
돌아가는지 확인한 다음 착수한다.

**This Month를 마지막에 두는 이유는 되돌릴 수 없는 약속이기 때문이다.**
한 달만 건너뛰어도 죽은 코너로 보인다. 앞의 둘이 안정된 뒤에 시작한다.

### 순서를 뒤집어야 하는 유일한 조건

아마존 재신청 계정은 **180일 내 적격 판매 3건**이 필요하다(재신청 2026-07-27 → 기한 약 2027-01-23).
2026년 10월까지 판매가 0건이면 **Prices를 앞으로 당긴다.** 아마존 링크가 가장 정직하게
들어갈 자리가 가격 비교이기 때문이다.

## 2. 코너 1 — `/seoul/` "Seoul, block by block"

### URL 구조

- 허브: `/seoul/`
- **개별 글은 `/blog/{slug}`에 그대로 둔다.** URL 마이그레이션은 이미 반증 완료된 사안이라
  건드리지 않는다. 허브는 새 글 컨테이너가 아니라 **큐레이션 면**이다.

### 페이지 구성 (위에서부터)

1. **한 줄 논지** — "서울은 한 도시가 아니다. 동네를 고르고 나서 호텔을 고른다."
2. **비교표** ← 이 코너의 핵심. 동네 / 성격 / 이런 사람에게 / 가장 가까운 역 / 묵기 좋은가 / 도보 소요
3. **동네 카드 그리드** (썸네일 + 한 줄 요약)
4. **"원하는 것으로 고르기"** — 조용한 곳 / 밤이 있는 곳 / 걷기 좋은 곳 / 처음 온 사람
5. **아고다 CTA 1개** (공시 포함) — "동네별로 숙소 비교"

비교표를 맨 위에 두는 이유: 우리 데이터에서 **비교형이 가장 잘 먹힌다**
(`shopping in busan vs seoul` CTR 11.76%). 카드 그리드가 먼저 오면 그냥 또 하나의 목록이 된다.

### 보유 자산 (7편)

`349` 을지로 · `351` 연남동 · `352` 문래동 · `353` 해방촌 · `354` 망원동 · `355` 익선동 · `163` 성수vs한남

### 다음 집필 순서 (씨앗 검증 통과분 우선)

서촌 → 북촌(익선동과 대비 서사가 이미 355에 있음) → 후암동 → 창신동 → 삼청동

**각도 규칙**: "카페 top 10"으로 쓰지 않는다. 우리가 이긴 방식은 **메커니즘과 역사**다 —
익선동은 1920년대 투기 개발이었고, 연남동 공원은 묻힌 철도이며, 망원동 이름은 1424년 정자에서 왔다.
대형 여행 매체가 안 쓰는 각도가 이것이다.

### 썸네일

- **전 동네 동일 크롭 16:9**, 하단 좌측에 동네명 플레이트(한글 병기: `Ikseon-dong 익선동`)
- 사진은 **골목·지붕선·거리 레벨** 우선. 랜드마크 사진은 쓰지 않는다 — 동네 성격이 안 보인다.
- 그리드에서 6장이 나란히 놓였을 때 **하나의 세트로 읽혀야 한다.** 색보정 톤을 맞춘다.

### 내부링크

- 각 동네 글 하단에 `Part of: Seoul by neighbourhood` 디바이더 → 허브 + **형제 동네 2개**
  (형제 선택 규칙: 성격이 가장 다른 곳 1 + 가장 가까운 곳 1. 비교 동기를 만든다)
- Travel 랜딩에 카드 1장
- 홈 섹션 타일 6번째

### 홍보

- 카드뉴스 1세트: "서울 동네 5곳, 원하는 것에 따라" — 비교표가 그대로 캐러셀이 된다
- 릴스: 익선동 편 (1920년대 개발자 이야기는 그 자체가 훅)

## 3. 코너 2 — `/prices/` "What things actually cost in Korea"

### 왜 이게 우리만 할 수 있는가

가격은 매달 바뀐다. 그래서 **론리플래닛도 로이터도 이걸 유지하지 않는다.** 한 번 쓰고 방치한다.
그리고 **구글이 스니펫으로 답을 끝낼 수 없다** — 표 전체가 답이기 때문이다.
090(아저씨)이 158,280 노출에 CTR 0.09%로 실패한 이유가 정확히 "스니펫으로 끝나서"였다.
가격표는 그 반대편에 있다.

### URL 구조

- 허브: `/prices/`
- 카테고리: `/prices/food` `/prices/transport` `/prices/beauty` `/prices/nightlife` `/prices/stay`
- **개별 품목 페이지는 만들지 않는다** (얇은 페이지 양산이 된다). 상세는 원본 글로 보낸다.

### 데이터 모델 — `content/data/prices.json`

```
{
  id, nameEn, nameKo, category,
  price: { min, max, currency: "KRW" },
  unit,                 // "1개", "1인분", "1박"
  where,                // "편의점", "다이소", "마트 5개입"
  asOf: "2026-08",      // 확인 시점 — UI에 반드시 노출
  sourcePost: "345",    // 검증한 글 (역링크)
  note,                 // "오픈프라이스라 매장별 상이"
  amazonQuery           // 선택: 해외 배송 비교용
}
```

**추출은 자동 파싱하지 않는다.** 34편 본문에서 정규식으로 긁으면 문맥을 잃는다
(예: `343`의 가격 37개 중 대부분은 리셀가 추이다). **한 항목씩 사람이 옮기고 출처 글을 단다.**

### 페이지 구성

1. **날짜를 크게** — "Verified in August 2026". 신뢰 장치이자 차별점이다.
2. 카테고리 앵커 내비
3. **정렬 가능한 표** — 품목 / 한글 / 가격 / 어디서 / 확인 시점 / 자세히(→ 글)
4. **"₩10,000으로 오늘 살 수 있는 것"** — 공유되는 훅 블록. 매달 갱신.
5. 아마존 자리 2곳:
   (a) 표 안 일부 행에 "해외 배송이 나은가?" 비교 — 가장 정직한 위치
   (b) 하단 CTA 1개

### 부패 방지 설계 ← 이 코너의 성패

**낡음을 UI에 드러낸다.**
- `asOf`가 90일 이상 지난 행은 **회색 처리 + "확인 필요" 배지**
- 허브 상단에 "전체 N개 중 M개가 90일 이내 확인됨" 카운터
- 점검 리듬: **매달 첫째 월요일** (editorial-surface.json의 기존 `homeReviewDay: Monday`와 맞춘다)

숨기지 않고 드러내는 이유: 낡은 표를 신선한 척하는 순간 코너 전체의 신뢰가 죽는다.
**드러내면 오히려 "이 사이트는 실제로 확인한다"는 증거가 된다.**

### 썸네일 / OG

카테고리별 정적 OG 5장. 디자인: 흰 배경 + 큰 `₩` + 품목 3개 실사 컷 + "AUG 2026" 스탬프.
**월이 바뀌면 스탬프만 교체**한다 — 그래서 매달 새 이미지를 만들 필요가 없다.

### 내부링크 — 이게 이 코너의 엔진이다

- **글 34편 각각**에 한 줄: "이 가격은 EpicKor 한국 가격표에서 다른 품목과 함께 볼 수 있습니다" → 허브
- 표의 모든 행 → 검증한 글
- **양방향이라 34개 글이 허브를 밀어올리고 허브가 34개 글로 되돌려보낸다.**
  지금 우리 사이트에서 가장 약한 게 세션 깊이인데 여기가 직접 때린다.

### 홍보

- 카드뉴스: "₩10,000으로 서울에서" — 매달 반복 가능한 포맷
- 릴스: 가격 비교는 시각적 훅이 강하다(편의점 vs 마트 vs 다이소 같은 물건)

## 4. 코너 3 — `/new/` "This Month in Korean Convenience Stores"

### URL 구조

- 허브: `/new/` (최신 호가 바로 보임)
- 월별: `/new/2026-09` — 아카이브가 쌓이면 그 자체가 자산이 된다

### 내용 모델

매달 6~10품목. 각 항목: 한글명 / 가격 / 어디서 / 실제로 뭔지 / 살 만한가(정직한 판정).

### 게이트 — 매달 통과해야 한다

2026-07-31에 확인한 것: **한국에서 뜬 신제품은 며칠 안에 영어 매체가 쓴다**
(Korea Times, Stripes Korea, VisitKorea English). `chestnut tiramisu cu`와 두쫀쿠가 이걸로 탈락했다.

그러므로 매달 **커버리지 게이트**를 통과한 품목만 싣는다. 통과 품목이 3개뿐이면
**3개짜리 호를 낸다. 채우지 않는다.**

### 리스크 관리

- **고정 발행일**: 매달 첫째 주 목요일
- 한 달을 거를 경우 **거른 사실을 페이지에 쓴다** (조용히 비우면 죽은 코너로 보인다)
- 3개월 연속 게이트 통과 품목이 5개 미만이면 **격월로 전환**하거나 접는다 — 판정 기준을 미리 정해둔다

### 홍보

이 코너가 릴스·카드뉴스 엔진이다. 신제품은 본질적으로 시각적이고 시의성이 있다.
**주의**: 릴스 소재 게이트(세로 영상이 실제로 존재하는지)를 주제 확정 전에 돌린다.

## 7. 하지 않기로 한 것 (재론 방지)

- **한국어 용어 사전 코너** — 090·082·210·301이 만드는 노출이 매력적으로 보이지만,
  그게 정확히 실패 사례다(158,280 노출 / CTR 0.09%). 사전을 코너로 만들면 실패를 규모화한다.
- **질문 받는 Q&A 페이지** — 분기 1,234클릭으로는 질문이 들어오지 않는다. 빈 방이 된다.
  인스타 팔로워와 웹 트래픽이 몇 배가 된 뒤 재검토.
- **개별 가격 품목 페이지** — 얇은 페이지 양산. 상세는 원본 글이 담당한다.
- **동네 글 URL 마이그레이션** — 이미 반증 완료. `/blog/`에 그대로 둔다.
