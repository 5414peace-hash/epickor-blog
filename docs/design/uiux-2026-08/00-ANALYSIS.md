실측 근거: 데스크톱 1440px + 모바일 390px에서 홈 / 블로그 346 / `/convenience-store` 허브 /
`/guides` 를 전수 캡처(스크래치패드 `ux/*.jpg`), `app/layout.tsx` · `app/globals.css` ·

## 결론 한 줄

**지금 UI는 "잘 만든 범용 Tailwind 뉴스 템플릿"이다. 치명적 결함은 없지만,
EpicKor가 실제로 파는 것 — 검증된 사실, 날짜 찍힌 가격, 비교 — 가 UI 표면에 전혀 드러나지 않는다.**
콘텐츠 전략(실행계획 챕터 1)은 뾰족해졌는데 화면은 아직 범용이다.

## 약점 (근거 포함)

### 1. 색이 브랜드가 아니라 소음이다
- 헤더 내비 9개 항목의 호버 색이 **전부 다르다**: red / emerald / blue / pink / violet /
  slate (`app/layout.tsx:54-86` 실측).
- 홈 섹션 라벨도 파랑(TRAVEL)·빨강(FOOD)·핑크(BEAUTY)·보라(CULTURE)·초록(BUSINESS)…
  **8개 이상의 강조색이 동급으로 경쟁**한다. 어느 색도 "EpicKor의 색"이 아니다.
- 유일한 고유 자산인 로고의 빨간 마침표(`EpicKor.`)가 그 소음에 묻힌다.

### 2. 타이포그래피에 주인이 없다
- 로고와 히어로 제목이 `font-serif` = **브라우저 기본 Times/Georgia**다. 선택된 서체가 아니라
  "지정 안 한" 서체. 허브 제목은 Inter Black, 본문은 Inter — 세리프/산세리프가 계획 없이 섞인다.
- `globals.css:12-13`의 `--font-geist-*` 토큰은 로드조차 안 되는 **죽은 토큰**(폰트는 Inter만 로드).
- 결과: 큰 제목이 나올 때마다 인상이 달라지고, 어디에도 "이 사이트의 목소리"가 없다.

### 3. 홈이 10개 동급 블록의 나열이다
검색바 → COMPARE 칩 → BROWSE 칩 → 최신 티커 → 히어로 그리드 → 인기 레일 → 섹션 타일 8개 →
카드뉴스 레일 → Plan Smarter → Reels → Business. **전부 흰 카드 + 굵은 라벨**로 같은 크기의
목소리를 낸다. 리드가 없으니 위계도 없다. 첫 화면에 진입 시스템이 3개(검색/COMPARE/BROWSE)나
경쟁하는 것도 같은 문제다.

### 4. 사이트의 실제 차별점이 화면에 안 보인다
- 우리 정체성은 "이번 달 확인한 가격, 한국어 출처 사실, 비교표"다. 허브 페이지에는
  `Checked August 2026` 배지가 있지만 **홈 카드·글 목록 어디에도 날짜/가격/검증 신호가 없다.**
- Hangul이 UI에 등장하지 않는다(허브 표 안에만). Korea-first 사이트인데 화면 언어는 무국적이다.

### 5. 아티클 페이지 진입부가 무겁다
- 1440px 풀블리드 히어로 이미지가 첫 화면을 다 차지해 **제목이 폴드 아래로** 밀린다(346 실측).
- 태그 필이 또 다른 파란색, 어필리에이트 박스는 노랑, 섹션 벨트는 빨강 — 본문 안에서도 색 소음.

### 6. 모바일 결함 (실측 버그)
- 헤더 내비가 가로 스크롤인데 **"Guides NEW" 배지가 "NE"로 잘린 채** 렌더된다(390px 실측).
  스크롤 가능하다는 힌트도 없어 뒤의 7개 메뉴는 사실상 발견 불가. 햄버거 메뉴 부재.
- "TODAY IN KOREA" 썸네일이 텍스트 박힌 카드뉴스 그래픽의 축소판 — 판독 불가 크기.

## 강점 (버리면 안 되는 것)

1. **정보 구조**: 허브/가이드 개념, 비교표 선행, 브레드크럼, 구조화 데이터 — 전부 옳다.
2. **본문 가독폭**과 `table-scroll` 표 처리 — 유지.
3. **속도**: 정적 렌더, JS 최소 — 어떤 리디자인도 이걸 해쳐선 안 된다.
4. 빨간 마침표 — 브랜드의 씨앗. 키울 것.

## 리디자인 제약 (대표님 지시 반영)

- **URL·라우팅·헤딩 구조·스키마·본문 HTML 불변.** 순수 표피(CSS 토큰·컴포넌트 마크업) 교체.
- 폰트는 next/font 자체 호스팅(외부 요청 0, CLS 관리).
- 단계별 배포 가능해야 함: 토큰 → 헤더/푸터 → 홈 → 아티클 크롬 → 허브.
