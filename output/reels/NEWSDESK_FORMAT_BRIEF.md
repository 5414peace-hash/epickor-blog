## 2. 뉴스 포맷이 구조적으로 고치는 것 세 가지

### ① 정보 속도 — Reels 2.3의 미해결 과제

CLAUDE.md 2026-08-17 진단: *"'움직임'이 아니라 '이산적 변화'를 센다. 376은 5초 동안 화면에서 바뀌는 게
자막뿐이었고 40초에 6컷이었다. 카드뉴스는 15초 주의에 7장을 준다."* 목표는 **≤1초/이벤트**.

**뉴스 화면은 이벤트를 푸티지 없이 만든다.** 로어서드가 바뀌고, 티커가 흐르고, 소스 크레딧이 붙고,
FIGURE 카드가 카운트되고, LIVE 점이 깜빡인다. **B롤 한 컷 위에서 초당 한 번씩 상태가 바뀔 수 있다** —
그게 다른 어떤 키트도 못 한 일이다.

### ② 푸티지 게이트 — 실패의 실제 원인이 사라진다

Reel `311`은 전략·씬플랜·스토리보드를 다 만든 뒤 **쓸 만한 세로 떡볶이 영상 0건**(10쿼리·29후보)이라
기획 전체가 폐기됐다. 그 후 만든 키트 3종(COUNTER·RECEIPT·DOSSIER)은 **푸티지를 아예 없애는 쪽**으로
갔다 — DossierKit 주석: *"NO PHOTOGRAPHY, deliberately… 세션 하나를 통째로 막은 제약이 팩샷이었다."*

**뉴스 패키지는 그 사이의 빈 자리다.** 뉴스 B롤은 관습적으로 **예시**지 **증거**가 아니다.
"한국에는 한 가지 음식만 담으려고 존재하는 두 번째 냉장고가 있습니다" 위에 일반적인 서울 주방 컷이
깔리는 건 뉴스 문법에서 정상이다.

**다만 이건 화면-말 불일치 면죄부가 아니다.** 2026-08-05 반려 사유가 정확히 그거였다(삼겹살 위에
"Sprite came 11 years late"). **뉴스가 주는 건 면죄부가 아니라 정직 장치다 — 로어서드가 컷의 정체를
밝힌다.** `FILE — SEOUL` / `ARCHIVE 2024` / `ILLUSTRATIVE` 라고 적으면 일반 컷이 정직해진다.
실제 방송이 그렇게 한다. **자료화면이라고 밝힌 자료화면은 거짓말이 아니다.**

### ③ AI 목소리 리스크가 오히려 내려간다

Reels 2.1 하드리젝트에 `unnatural narration`이 있다. 그런데 **방송 낭독은 원래 형식적이다.**
대화체 TTS의 어색함은 결함으로 들리지만, 앵커 톤의 절제된 낭독은 **장르로 읽힌다.**
유머도 같은 이유로 산다 — **뉴스 패러디의 웃음은 억양이 아니라 "사소한 것을 정색하고 다루는 낙차"에서
나온다.** TTS가 감정을 잘 못 싣는 게 여기서는 오히려 무기다.

## 5. 키트 설계 — NEWSDESK

### 길이: 22~28초 (기존 32~42초에서 단축)

시청 중앙값이 7초다. **같은 7초라도 40초짜리에서는 완주율 18%, 25초짜리에서는 28%다.**
인스타는 완주율을 본다. 뉴스 패키지는 원래 짧고, 짧은 게 이 포맷의 장점이지 타협이 아니다.

### 3막 구조

```
[00.0–03.0]  COLD OPEN   BREAKING 밴드 + 첫 프레임에 사건이 벌어지는 푸티지
                         앵커 첫 문장 = 판정문 한 줄
[03.0–07.0]  HEADLINE    로어서드가 주장 확정 + 티커 시작
[07.0–18.0]  PACKAGE     B롤 3~4컷. 컷마다 로어서드 교체 + FIGURE 카드 1회
[18.0–23.0]  KICKER      ★ 반드시 영상에서 벌어지는 리빌. 그래픽 아님
[23.0–26.0]  OUTRO       빨간 칩 + 뱅크 문구 1개, 무음
```

### 화면 상시 요소 (= 정보 속도의 엔진)

| 요소 | 위치 | 변화 주기 | 역할 |
|---|---|---|---|
| **EPICKOR NEWS 버그** | 좌상단, 작게 | 고정 | 브랜드 일관성. 릴스 라이브러리 전체의 마크 |
| **로어서드** | 하단 밴드 위 | **컷마다** | 주장 확정 + 컷 정체 표기(FILE/ARCHIVE/ILLUSTRATIVE) |
| **티커** | 최하단 스트립 | 상시 흐름 | 푸티지 없이도 화면이 계속 바뀐다 |
| **소스 크레딧** | 로어서드 우측 | 사실 등장 시 | `SEOUL METRO` 등. 신뢰 + 유머의 정색 |
| **FIGURE 카드** | 중앙, 1회만 | 카운트업 | 숫자를 사건으로 만든다 (CounterKit 검증 기법) |
| **자막** | 캡션 밴드 | 구문 단위 | `y=1400` 이하 고정. 로어서드와 겹치지 않게 **하단 두 층 분리 설계 필수** |

⚠ **가장 큰 설계 리스크**: 로어서드·티커·자막이 전부 하단에 몰린다. 캡션 배제선(`y≥1400`)과
로어서드 상단(`y≤1340`)이 이미 규칙으로 있으므로 **티커를 자막 아래 최하단 40px에 눌러 넣고
로어서드를 자막 위로 올리는 3층 배치**를 렌더 전에 1080×1920 실측으로 확인한다.

### 유머의 작동 방식 — 톤 규칙

**웃음은 대본이 웃기려 해서가 아니라 형식이 정색해서 나온다.**

- 앵커는 **절대 농담하지 않는다.** 사소한 사실을 국가적 사안처럼 읽는다.
- 로어서드는 **진짜 뉴스처럼** 쓴다: `KIMCHI STORAGE CRISIS AVERTED`, `SOURCE: SEOUL METRO`
- 티커에 **본 내용과 무관한 소소한 한국 사실**을 흘린다 — 실제 뉴스 티커의 리듬이자 개그 자리
- 금지: 이모지, 느낌표, "you won't believe", 밈 폰트. **정색이 무너지면 포맷이 죽는다**

## 7. 제작 순서 (승인 후)

```
0. 대표님 승인    ── 신규 보이스 레인 `anchor_deadpan` + 포맷 파일럿 자체
1. 보이스 오디션  ── npm run reels:tts  (Daniel 외 2종, 같은 8~12초 문장)  → 대표님 선택
2. 소재 게이트    ── npm run footage:gate -- --topic dongmyo --query "..."  → 컨택트시트 육안
3. strategy.md    ── output/reels/2026-09-XX_dongmyo-news/strategy.md (Viral Fit 점수 포함)
4. 대본 + 비트표  ── 컷·로어서드·티커·FIGURE를 프레임 번호로 확정
5. NewsdeskKit    ── remotion/NewsdeskKit.tsx 작성 + 파일 지정 타입체크
                     (npx tsc --noEmit --jsx react-jsx ... remotion/NewsdeskKit.tsx
                      — remotion/은 tsconfig exclude라 전체 tsc는 검사하지 않는다)
6. 오디오 베드    ── 컷 프레임에 맞춘 stdlib 합성 + 스팅어
7. 렌더           ── npm run reels:render
8. QA 3종         ── reels:qa-audio (0.6초 무음 차단) / reels:qa-cuts (화면-말 대조) /
                     연속성 -2~+2 프레임 + 재생대역(400Hz~9kHz) 오디오 측정
9. 대표님 폰 리뷰 ── 소리 on/off 양쪽
```

**폴더는 `output/reels/{YYYY-MM-DD}_{slug}/` 평평하게. `final/` 없음. 산출 렌더는 최종 1개만 남긴다.**
